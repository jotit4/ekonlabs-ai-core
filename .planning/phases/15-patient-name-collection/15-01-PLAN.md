<objective>
Add name-based booking deferral to booking_node.

NAME-02: When a patient confirms a slot but no patient_name is in state, booking_node does NOT create a Google Calendar event. Instead, it defers and signals generation_node to collect the name first by setting name_collection_active=True and booked_slot.

NAME-03: When patient_name IS in state (captured in Turn 2), booking_node creates the event with the patient's name in the title: "Turno — {patient_name}".

NOTE: In Turn 2 (name captured), the calendar event is created INLINE in generation_node (not in booking_node), because the name comes from the patient's Turn 2 message and booking_node would not detect a booking keyword in "María López". So booking_node only needs the title passthrough when called with patient_name already in state (rare case, e.g. retry flows). The inline creation in Phase 15-02 is the primary path.

Also add name_attempts: NotRequired[int] to state.py — used in generation_node (Plan 15-02) to count how many times the agent has asked for the patient's name.
</objective>
